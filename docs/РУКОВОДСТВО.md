# «ЭТИМ» — кассовый автомат: полное руководство по эксплуатации

Эмулятор кассы АО «ЭТИМ» (Санкт-Петербург, 1994–95) на чистом Python.
**Интернет не нужен вообще**: только Python 3 с Tkinter в стандартной
поставке, сторонние пакеты не устанавливаются, сеть не используется.

Проверено: Python 3.14, Windows. Все команды выполняются в папке проекта.

---

## 1. Быстрый старт (проверка за 30 секунд)

```powershell
# желательно для корректной кириллицы в консоли:
$env:PYTHONUTF8 = 1

python main.py            # открыть окно кассы (режим demo51 — рабочий по умолчанию)
```

Что сделать в окне:

1. На индикаторе уже горит `0    000` — это стартовое состояние.
2. Наберите `5`, `0`, `0` (мышью или клавиатурой) → индикатор покажет ввод.
3. Нажмите **СУММА** — позиция зарегистрирована.
4. Нажмите **ОПЛ** — касса печатает чек, он появляется в ленте справа.
5. Лента содержит шапку, номер, кассира, позиции, итог — «чек живой».

Если экран не отвечает на нажатия — перезапустите `python main.py`
(устаревшие версии страдали «залипанием» экрана, исправлено в коммите
`ed6c76c`).

## 2. Запуск и опции командной строки

| Команда | Что делает |
| --- | --- |
| `python main.py` | окно кассы, режим **demo51** (по умолчанию) |
| `python main.py --backend recovered` | настоящая прошивка ETIM: включение, бут, самотест (см. §7) |
| `python main.py --backend etim` | настоящие байты ПЗУ на ядре 8051 (бут, без GUI-функций кассы) |
| `python main.py --list` | список режимов и образов ПЗУ, без запуска |
| `python main.py --selftest` | проверка модулей, без окна |
| `python main.py --headless 5` | погонять эмуляцию 5 секунд и распечатать статус |
| `python main.py --self-test` | плата сама показывает картинку и печатает образцовый чек (для `demo51`/`etim`) |
| `python main.py --dump ПУТЬ` | свой .c-дамп декомпиляции (для `recovered`) |
| `python main.py --help` | все опции |

Тесты (без окон):

```powershell
python -m unittest discover -s tests -q     # 426 тестов, ожидается OK
python tools/_bench.py                      # замер производительности
```

## 3. Устройство окна

```
┌──────────────────────────────────────────────────────────────┐
│ Меню: Касса | Вид | Справка                                  │
├───────────────────────────────────┬──────────────────────────┤
│  ИНДИКАТОР (8 знакомест)          │  ЛЕНТА ЧЕКА              │
│  0    000                         │  шапка, позиции, итог    │
├───────────────────────────────────┴──────────────────────────┤
│ КЛАВИАТУРА: [7 8 9][4 5 6][1 2 3][0 00 .] │ СУММА ОПЛ X …   │
│             нижний ряд: КАССИР СЕРВИС РЕЖИМ ЧЕК КС Z ПИТ     │
├──────────────────────────────────────────────────────────────┤
│ Строка состояния: режим • ошибки • клавиш • последняя •       │
│ принтер: готов/занят • экран: 8 x 1                          │
└──────────────────────────────────────────────────────────────┘
```

* **Индикатор** — виртуальный знаковый индикатор 8×1 (по умолчанию).
  Режимы табло (`20×1 касса`, `20×2`, `16×1 ценник`, `8×1`, `40×1`)
  переключаются клавишей **РЕЖИМ**.
* **Лента чека** — окно справа (управляется меню «Вид»).
* **Строка состояния** показывает: режим платы, ошибки (если были),
  число кнопок, последнюю нажатую клавишу, состояние принтера и размер
  индикатора.
* Обновление экрана вручную — **F5** (или меню «Касса → Обновить экран»).

## 4. Клавиатура

### 4.1 Экранная (клик мышью)

```
  7   8   9  │ СУММА
  4   5   6  │ ОПЛ
  1   2   3  │ X
  0  00   .  │ ИТОГ
             │ ВВОД
             │ СБРОС
             │ ОТМЕНА
─────────────┴──────────────
 КАССИР СЕРВИС РЕЖИМ ЧЕК КС Z ПИТ
```

Каждая кнопка объёмная (классический вид), разного цвета по группам:
цифры, арифметика, служебные, режимы, принтер, опасные.

### 4.2 Физическая клавиатура

| Клавиша | Действие кассы |
| --- | --- |
| `0`–`9` | цифры ввода |
| `.` или `,` | десятичная точка (копейки) |
| `Enter` | ВВОД |
| `Esc` | СБРОС / ОТМЕНА |
| `Backspace` | СБРОС (стирание) |
| `Delete` | ОТМЕНА |
| `←` `→` | стрелки влево/вправо |
| `Пробел`, `Tab` | ПРОБЕЛ, ТАБ |
| `F1` | КАССИР |
| `F2` | СЕРВИС |
| `F3` | РЕЖИМ (переключение режима индикатора) |
| `F4` | ЧЕК |
| `F5` | обновить экран |
| `F6` | Z (Z-отчёт) |
| `F7` | ПИТ (подача бумаги) |
| `F8` | КС (X-отчёт) |

Внутренние имена клавиш (`press()/release()`) принимают и английские
псевдонимы: `PAY`→ОПЛ, `CANCEL`→ОТМЕНА, `CLEAR`→СБРОС, `ENTER`→ВВОД,
`SUBTOTAL`→ПОДЫТОГ, `DISCOUNT`→СКИДКА и т. д. (см. `board/keyboard.py`,
`ALIASES`).

## 5. Типовая продажа (режим demo51)

Порядок действий кассира:

1. **Ввод суммы**: цифры `1 0 0 0` = 10.00 (ввод в копейках; клавиша `.`
   фиксирует копейки, `00` — быстрые нули).
2. **СУММА** — зарегистрировать позицию: сумма позиции добавляется к
   итогу, строка печатается на чек.
3. **ПОДЫТОГ** — показать промежуточную сумму без печати.
4. **ИТОГ** — показать итог по чеку.
5. **ОПЛ** — приём наличных и завершение чека:
   * хватает денег → печатается итог, «наличными», «сдача»,
     «спасибо за покупку»;
   * не хватает → строка «недостаточно» (`nedostato~no`).
6. **ОТМЕНА** — сторнировать последнюю позицию (печатается строка
   `otmena` + сумма).
7. **СБРОС** — очистить текущий ввод.

Содержимое чека (демо): шапка `kassa 'tim`, `demo-programma`,
`(ne original!)`, черта, `id=…`, `kassir 01`, дата, позиции, итог,
наличными/сдача, «спасибо за покупку». **Это стенд-ин**: настоящий
машинный код 8051, но не оригинальная прошивка ETIM — надпись на чеке
об этом честно говорит.

> Служебные клавиши `X`, `КАССИР`, `СЕРВИС`, `ЧЕК`, `КС`, `Z`, `ПИТ` в
> демо принимаются платой, но их собственная обработка живёт в
> оригинальной прошивке (см. §7).

## 6. Режимы запуска (`--backend`)

| Режим | Что внутри | Достоверность |
| --- | --- | --- |
| **`demo51`** (по умолчанию) | `firmware/demo/cashier.asm`, собранная ассемблером проекта | настоящий машинный код 8051 на той же плата; **единственный режим с полной интерактивной продажей**; не оригинальная прошивка |
| **`recovered`** | оригинальные байты прошивки ETIM на ядре 8051 (`recover/realrun.py`) + восстановленный псевдокод | включается с настоящего вектора сброса (CPU `0x0A06`); на экране — **штатный самотест RAM самой прошивки** (`'  .h0000'` = падающий адрес `0000h`); верхняя половина ПЗУ `0x8000..0xFFFF` в дамп не вошла и озвучивается честно |
| **`etim`** | ядро 8051 + дамп `nm27c512n.hex` после rebasing | байты настоящие, бут реальный; функционал кассы недоступен без второй половины ПЗУ |

### 7.1 Почему у `recovered` экран показывает самотест, а клавиши «не работают»

Это **не поломка, а честное состояние настоящей прошивки**:

* ПЗУ-дамп — только нижние 32 КиБ (картинка записана по смещениям
  программатора `0x8000..0xFFFF`, на процессоре это `0x0000..0x7FFF`);
  включение идёт по настоящему вектору сброса — это доказано байтами.
* Прошивка при старте прогоняет **самотест внешнего ОЗУ** по диапазону
  `0x0000..0x1FFF`; в нашей плате в этом диапазоне пока декодируется
  8255 (гипотеза `WIRING: PPI_BASE=0x0000`), поэтому тест честно падает
  на адресе `0000h` и выводит его на индикатор — экран `'  .h0000'`.
* Клавиатурный цикл настоящей прошивки живёт в Timer-1 ветке, которую
  самотест до этого не даёт запустить, поэтому нажатия в этом режиме
  пока не обрабатываются. Открытая находка: перенести декод 8255 вне
  диапазона самотеста и разобраться, почему прошивка рано уходит в
  «выключение» (подробности — `docs/usage.md` §4.3).

Интерактивная работа — это режим `demo51` (§5).

## 8. Строка состояния и индикатор: как читать

* `клавиш: N` — сколько кнопок на экране; `последняя: ИМЯ` — что жали.
* `принтер: готов/занят` — состояние виртуального принтера
  (во время печати — «занят»).
* `экран: 8 x 1` — текущий режим табло.
* Надпись `ОШИБКА ЭКРАНА: …` в строке состояния означает сбой чтения
  платы; экран при этом показывает `ОШИБКА ЭКРАНА`, но не падает —
  через пару секунд содержимое восстанавливается автоматически.

## 9. Типовые неполадки

| Симптом | Причина / действие |
| --- | --- |
| Окно открылось, но пусто | подождите ~0.3–1 с (бут) ; если пусто — обновитесь до коммита `ed6c76c` или новее (чинит «залипший» экран) |
| Экран целиком залит, цифры не видны | то же исправление `ed6c76c` (точка ошибочно считалась горящей) |
| `recovered`: экран `  .h0000` | самотест RAM настоящей прошивки, см. §7.1 — это её честный вывод |
| Нажатия не дают эффекта в `recovered` | см. §7.1 — клавиатура прошивки ещё не восстановлена; используйте `demo51` |
| Тест упал | `python -m unittest <модуль> -v`, набор зелёный по умолчанию (426/OK) |
| Кириллица в консоли кракозябрами | `$env:PYTHONUTF8 = 1` перед запуском |
| `git` отвечает «BUG (fork bomb)» | используйте прямой путь `C:\Program Files\Git\mingw64\libexec\git-core\git.exe` (известная поломка обёртки Git в этой системе) |

## 10. Границы достоверности (честная сводка)

* **Оригинальная прошивка** восстановлена из декомпиляции и байтов ПЗУ;
  включается и исполняется по-настоящему, но клавиатурный цикл пока не
  доведён (§7.1). Всё, что выдается в `reason`/`--headless`, — факты
  с адресами, а не домыслы.
* **`demo51`** — стенд-ин для отработки сценария «продажа» на той же
  плата; чек честно помечен как демо.
* Гипотезы по железу (место 8255, INT0 = линия отключения питания)
  помечены `HYPOTHESIS`/`CONFIRMED` в `board/cashboard.py` и
  `docs/board_contract.md`.
