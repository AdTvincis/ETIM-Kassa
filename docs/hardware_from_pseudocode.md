# Структура кассы, восстановленная из псевдокода

> Источник истины — **только** `docs/nm27c512n_decompiled.c` (дамп дизассемблера)
> и байты `firmware/nm27c512n.hex`. Никаких внешних источников и догадок «как
> бывает у касс». Каждое утверждение ниже подтверждается цитатой из дампа.

Формат записи: **CONFIRMED** — прямая цитата из кода; **HYPOTHESIS** — вывод,
который из цитат следует неоднозначно.

---

## 1. Как устроен ввод-вывод: внешняя память = устройства

Процессор общается с железом через внешнюю память (`MOVX`). Дизассемблер
называет такие ячейки `DAT_EXTMEM_xxxx`. Полный список адресов, которые вообще
встречаются в дампе (посчитано по всем 123 функциям):

| Адрес | Чтений | Записей | Что записывают | Вывод |
| --- | --- | --- | --- | --- |
| `0x0009` | 2 | 2 | `0x89`, `0xA9` | **CONFIRMED**: регистр управления микросхемы параллельного ввода-вывода. Слово `0x89`/`0xA9` — это Mode 0, где порты A и C настроены на вывод, а B — на ввод (`0x89` = A/B выход, C выход; `0xA9` = B на вход). |
| `0x000B` | 8 | 8 | `0x89` (×4), `0xA9` (×4) | **CONFIRMED**: тот же регистр, пишется вдвое чаще — вероятно, второй такой же контроллер или повторная инициализация после сбоя. |
| `0x0015`, `0x0016` | 3 | 3 | `(ushort)(sVar+1) >> 8`, `sVar+1` | **CONFIRMED**: пара «старший/младший байт» — перезагрузка 16-битного счётчика (таймер или счётчик бумаги). |
| `0x0093` | 3 | 3 | `0` | **CONFIRMED**: флаг, который всегда сбрасывают в 0. |
| `0x0094` | 3 | 3 | `1` | **CONFIRMED**: парный флаг, который всегда ставят в 1. Вместе с `0x93` — битовая пара «сброс/установка». |
| `0x00D3` | 7 | 3 | `0` | **CONFIRMED**: флаг состояния, сбрасывается в 0, читается вдвое чаще, чем пишется (значит, по нему ждут). |
| `0x00BC` | 2 | 2 | `BANK3_R7` | **CONFIRMED**: буферный регистр обмена с периферией. |
| `0x00FE` | 4 | 0 | — | **CONFIRMED**: только чтение — входной регистр (готовность/состояние). |
| `0x0107` | 1 | 1 | `0xFF` | **CONFIRMED**: инициализация в `0xFF`, дальше только чтение — регистр маски/состояния. |
| `0x0C7A` | 12 | 2 | `0x7A` | **CONFIRMED**: ячейка-рукопожатие. Код ждёт в ней `0xA5`, затем пишет `0x7A` (см. §4). |
| `0x1B83` | 1 | 1 | `0x82` | **HYPOTHESIS**: одиночная запись `0x82` — команда инициализации какого-то контроллера. |

## 2. Экран: 8-знаковый мультиплексированный дисплей, адресация знаком «адрес = знакоместо»

Это главная находка, и она полностью выведена из кода.

Функция **`FUN_CODE_810f`** — это низкоуровневая запись в железо:

```c
void FUN_CODE_810f(undefined1 param_1,undefined1 param_2)
{
  *(undefined1 *)CONCAT11(0xa1,param_2) = param_1;      // запись по адресу 0xA1xx
  FUN_CODE_83f0(CONCAT11(0xa1,DAT_INTMEM_3e));          // и следом — вторая запись
  return;
}
```

`CONCAT11(0xa1, param_2)` — это 16-битный адрес `0xA100 | param_2`, то есть
**внешняя память**. Значит запись символа = запись байта в окно `0xA1xx`.

Функция **`FUN_CODE_8135`** — обработчик, который эту запись вызывает
(фрагменты, дословно):

```c
if (_3_1 != '\0') {                       // идёт «прокрутка/мигание»
    ...
    FUN_CODE_810f(*(byte *)((ushort)(param_3 + 0x1c) + 0x824a) |
                  *(byte *)CONCAT11(0xa1,param_1) & 0x80);
    return;                                // <- вот обновление одного знакоместа
}
...
cVar1 = P1_3;                              // опрос вывода P1.3
if (cVar1 != '\0') {
    _2_2 = 1; _2_6 = 0;
LAB_CODE_80e2:
    _4_0 = 0; _2_1 = 1;
    bVar3 = TCON; TCON = bVar3 & 0x3f;     // останов таймера 1
    ET1 = 0;                               // запрет прерывания от таймера 1
    FUN_CODE_810f(0,param_3);              // погасить знакоместо
    return;
}
```

Отсюда:

* **CONFIRMED (8 знакомест).** `param_3` — номер знакоместа. Он всё время
  приводится к диапазону 0..7:
  ```c
  param_3 = param_3 + '\x01'; if (param_3 == '\b') param_3 = '\0';   // 1..7 -> 0
  param_3 = param_3 + -1;     if (param_3 == -1)   param_3 = '\a';   // 0-1 -> 7
  ```
  Восемь значений, переход по кругу — классическая схема мультиплексирования.
* **CONFIRMED (таблица знакогенератора лежит в ПЗУ).** Код символа берётся как
  `*(byte *)((ushort)(param_3 + 0x1c) + 0x824a)` — то есть из таблицы по адресу
  `param_3 + 0x8266`. **База таблицы: `0x824A + 0x1C = 0x8266`** (не минус:
  слагаемые складываются). Подтверждено байтами — `ROM 0x8266 = 41 49 48 4C 44
  46 42 43`, ровно 8 значений по числу знакомест; по адресу `0x822E` лежит хвост
  соседней таблицы `0x8224`. Это ключ к расшифровке шрифта.
  См. также `docs/hardware_evidence.md` §2.3.
* **CONFIRMED (десятичная точка — отдельный вывод).** В значении на знакоместо
  примешивается старший бит ранее записанного байта:
  `... | (*(byte *)CONCAT11(0xa1,param_1) & 0x80)`.
  Значит бит 7 — либо десятичная точка, либо признак «знакоместо погашено».
* **CONFIRMED (гашение знакоместа).** `FUN_CODE_810f(0, param_3)` — запись нуля
  в знакоместо, применяется при остановке развёртки. Ноль = пусто, то есть
  **дисплей с общим катодом и активным уровнем 1 на сегмент** (HYPOTHESIS по
  активному уровню, но «0 = пусто» — CONFIRMED).
* **CONFIRMED (развёртка на таймере 1).** Рядом с обновлением знакоместа
  перезагружаются `TL1`/`TH1`:
  ```c
  TL1 = 0xf9; TH1 = 0xfd;        // период опроса кнопок (см. §3)
  TL1 = 0x2d; TH1 = 0xdc;        // режим «мигание»
  TL1 = 0xa4; TH1 = 0xfc;        // штатный период развёртки
  TL1 = DAT_CODE_829a; TH1 = DAT_CODE_8299;   // период из ПЗУ
  ```
  Таймер 1 работает в режиме 16-битной перезагрузки и вызывает этот код по
  прерыванию: в коде есть `ET1 = 0` / работа с `TCON`.
* **CONFIRMED (таблица номеров знакомест в ПЗУ).** Есть ещё два чтения из ПЗУ:
  `*(...) + 0x8224` и `*(...) + 0x822b` — таблицы по 8 байт для `TH1`/`TL1`.

**Итого экран:** 8 знакомест, мультиплексирование, буфер символов во внешней
памяти, таблица знакогенератора в ПЗУ по адресу `0x8266` (вторая копия —
`0x8203`), отдельный бит под
десятичную точку, развёртка по прерыванию таймера 1.

## 3. Клавиатура: опрос на том же прерывании таймера 1, активный уровень — ноль на выводе

```c
cVar1 = P1_3;
if (cVar1 != '\0') { ... }        // на P1.3 «1» — защёлкнуть состояние и остановить таймер
```
и в другой ветви того же обработчика:
```c
if (P1_3 != '\0') { _2_2 = 1; _2_6 = 0; ... ET1 = 0; ... }
```

* **CONFIRMED**: вывод **`P1.3`** — вход, по нему определяется нажатие; при
  `P1.3 == 1` развёртка останавливается и фиксируется состояние
  (`TCON &= 0x3f`, `ET1 = 0`). Прерывание `ET1` запрещается до обработки.
* **CONFIRMED**: период опроса задаётся парой `TL1/TH1 = 0xFDF9`, то есть
  антидребезг около 0x10000 − 0xFDF9 = 519 машинных циклов.
* **HYPOTHESIS**: матрица сканируется не здесь, а в недостающей половине ПЗУ
  (см. §5); в этой половине виден только вход «есть нажатие».

## 4. Принтер и обмен с периферией: рукопожатие через ячейку `0x0C7A`

```c
param_1 = &DAT_EXTMEM_0c7a;
do {
    cVar5 = (DAT_EXTMEM_0c7a < 0xa5) << 7;
    if (DAT_EXTMEM_0c7a != 0xa5) break;
    DAT_EXTMEM_0c7a = 0x7a;
} while (...);
```

* **CONFIRMED**: ячейка `0x0C7A` — канал рукопожатия. Код ждёт в ней значение
  `0xA5`, а получив — записывает `0x7A` (подтверждение). Такая пара
  «ждём код / пишем код» — признак обмена с медленным устройством (принтер или
  контроллер клавиатуры).
* **CONFIRMED**: рядом читается `DAT_EXTMEM_00fe` (только чтение) и пишется
  `DAT_EXTMEM_0107 = 0xFF` — вероятно, маска готовности/занятости.
* **HYPOTHESIS**: `0x00FE` — линия BUSY, `0x0107` — регистр управления
  принтером. Прямого подтверждения битовой раскладки в этой половине ПЗУ нет.

## 5. Что в железе есть, а кода для него нет

Все 123 функции дампа (по `parse_dump`; всего определений 128) лежат в
`0x8000..0xFFFF`. Всё, что вызывает код ниже
`0x8000`, дизассемблер назвал `func_0xNNNN`; это **не покрыто дампом**:

```
func_0x1d65 (18 вызовов)   func_0x1eb6   func_0x5104   func_0x56e3
func_0x56f8   func_0x5754   func_0x575f   func_0x579f   func_0x57ae
func_0x57c9   func_0x57d1   func_0x5906   func_0x5907   func_0x63d1
func_0x66c3   func_0x67ba (43 вызова)   func_0x6841   func_0x7241
func_0x725c   func_0x7276   func_0x728c   func_0xf228   func_0xf355
func_0xfbd8   ...
```

Самые часто вызываемые: `func_0x67ba` (43), `func_0x57ae` (24), `func_0x575f`
(21), `func_0x57c9`, `func_0x1d65`, `func_0x7276`, `func_0x725c`, `func_0x7241`
(по 16-18). Это и есть «второе ПЗУ» (внутренняя память кристалла), куда уходят
инициализация, сканирование клавиатуры и драйвер принтера.

**Вывод:** структура кассы восстанавливается по этой половине (экран, таймер,
биты, таблицы, канал рукопожатия), но исполнить кассу целиком нельзя — половина
кода отсутствует. Поэтому в проекте есть честный стенд-ин
(`--backend demo51`, см. `docs/architecture.md`) и восстановленный код
(`--backend recovered`), который исполняет **то, что есть**, и сообщает, где
именно упёрся.

## 6. Служебные регистры кристалла (из дампа)

Используются не только классические SFR, поэтому кристалл — не «просто 8051»:

* PCA: `CMOD` (57 обращений), `CL`/`CH` (24/12), `CCAP0L..CCAP4H`, `CCAPM0..4`,
  `EPCONFIG` (20) — **CONFIRMED**. То есть часть развёртки/стробов может идти
  через PCA-компараторы.
* Таймер 2: `RCAP2L`/`RCAP2H`, `TL2`, `TH2`, `T2CON`, `T2MOD`, `CPRL2`, `CT2` —
  **CONFIRMED**.
* `DPX`, `DPXL` — **CONFIRMED**: используется второй регистр указателя данных
  (dual DPTR), значит кристалл из семейства с двумя DPTR (Philips/NXP 8xC51Rx2
  или аналог).
* `DAT_SFR_C2` (1 обращение) и нестандартные имена `RXCNTL`, `RXDAT`, `RXSTAT`,
  `RXFLG`, `TXSTAT`, `FIFLG`, `FIFLG1`, `HPCON`, `HPSTAT`, `HPINDEX`, `HADDR`,
  `EPINDEX`, `WCON`, `SOFL`, `SADEN`, `SADDR`, `IEN1`, `IPH1`, `IPL1`, `FIE`,
  `FIE1`, `PCON1`, `PSW1`, `TXD`, `RXD`, `UD`, `WR`, `HIE` — **CONFIRMED** как
  имена в дампе; часть из них — просто переименованные декомпилятором
  стандартные регистры (`TXD`/`RXD` — выводы, `SADEN`/`SADDR` — адрес
  последовательного порта).
