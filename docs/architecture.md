# Архитектура проекта «Касса ЭТИМ» — эмулятор AT89C55VD на Python

## Что дано

| Файл | Что это |
| --- | --- |
| `nm27c512n.c` | Дизассемблированный (Ghidra) код прошивки кассы, 128 определений функций (`parse_dump` находит 128 из 128), все адреса функций — в диапазоне записей `0x8000..0xFFFF` (адресная сетка Ghidra) |
| `firmware/nm27c512n.hex` | Дамп ПЗУ 27C512: 32768 байт; записи Intel HEX лежат по смещениям программатора `0x8000..0xFFFF` |
| `docs/rom_strings.txt` | Извлечённые строки из дампа |

Строка `Copyright (C) 1994-95, AO "ETIM" SPb` находится в записи `0x8026`.

### Две сетки адресов (читать перед всеми таблицами)

Записи дампа — **смещения программатора, а не CPU-адреса**: сама картинка
занимает нижние 32 КиБ пространства команд процессора, `0x0000..0x7FFF`
(rebasing `−0x8000` выполняет `m8051/firmware_profile.py` при загрузке;
см. его докстринг с доказательствами). Дальше и в соседних документах:

* **«запись `0xNNNN`»** — адрес в файле hex (сетка Ghidra: `0x8000..0xFFFF`);
* **«CPU `0xNNNN`»** — адрес, который исполняет процессор: `запись − 0x8000`.

Доказательство в байтах: первая запись (`0x8000`) — `02 0A 06` =
`LJMP 0x0A06`, настоящий вектор сброса, который имеет смысл только на CPU
`0x0000`; цель `0x0A06` лежит внутри той же картинки (запись `0x8A06`) и
содержит типовой старт 8051 (`CLR P3.4 / CLR A / MOV R0,#7Fh / …` — очистка
внутренней RAM). Векторы прерываний тоже на месте (CPU `0x0003`, `0x000B`,
`0x0013`, `0x001B`, `0x0023`), и при rebasing прошивка исполняется миллионы
циклов, не попадая в несуществующий адрес. Чего в дампе **нет** — верхней
половины `0x8000..0xFFFF`: обращение туда останавливает CPU с честным
сообщением.

## Цель

Python-эмулятор процессора 8051 (AT89C55VD) + эмуляция самой кассы:
экран, клавиатура, печать чеков. Интерфейс — **Tkinter**, классические
объёмные кнопки, тёмный фон.

## Два способа запустить кассу

Заказчик сформулировал требование так: «восстановить декомпилированный код,
перебрать его полностью, чтобы он стал хоть как-то рабочим». Поэтому проект
делает обе вещи сразу и не смешивает их:

| Режим | Ключ | Что внутри | Насколько достоверно |
| --- | --- | --- | --- |
| **Восстановленный код** | `--backend recovered` | `docs/nm27c512n_decompiled.c` → парсер (`recover/parse.py`) → AST (`recover/cparse.py`) → интерпретатор (`recover/interp.py`) → HAL к железу кассы | Логика настоящая для адресов `0x8000..0xFFFF`; всё, что ниже — выдумка декомпилятора, и это честно помечается |
| **Демонстрационная программа** | `--backend demo51` | `firmware/demo/cashier.asm`, собранная `tools/asm51.py`, исполняется ядром `m8051` | Стенд-ин: настоящий машинный код 8051, но не оригинальная прошивка |
| **Дамп ПЗУ** | `--backend etim` | `m8051.CPU8051` на реальных байтах `firmware/nm27c512n.hex` | Байты настоящие, но нижняя половина ПЗУ не сохранилась (см. ниже) |

`main.py --list` показывает варианты, `main.py --headless 5` прогоняет выбранный
режим без окна и печатает состояние.

## Контракт `HardwareBus` (m8051/bus.py)

- `tick(cycles)` — продвинуть периферию на N машинных циклов (1 МГц при 12 МГц кварце).
- `ext_read(addr, code=False)` / `ext_write(addr, value)` — внешняя память (MOVX),
  туда же отображается ППИ 8255 (адреса `0x0000..0x0003`).
- `port_read(port)` — уровни на выводах порта (0..3), которые «прикладывает» плата.
- `port_write(port, value)` — значение, защёлкнутое процессором.
- `port_change(port, old, new)` — изменение защёлки (для стробирования).
- `serial_write(byte)` / `serial_read()` / `serial_available()` — UART.
- `irq_requested()` — битовая маска `IRQ_*`.

## Модель памяти, которую ждёт восстановленный код

Декомпилятор обращается к железу через внешнюю память (MOVX). Адрес — это и
есть устройство:

| Адрес | Что это | Достоверность |
| --- | --- | --- |
| `0x0000..0x0003` | ППИ 8255: порт A, порт B, порт C, регистр управления (слова `0x89`, `0xA9`) | подтверждено значениями в коде |
| `0x0009`, `0x000B` | второй управляющий регистр ППИ (пишутся те же `0x89`/`0xA9`) | подтверждено |
| `0x0015`, `0x0016` | младший/старший байт счётчика (перезагрузка таймера) | гипотеза |
| `0x0093`, `0x0094`, `0x00D3` | флаги/состояние, пишутся 0/1 | гипотеза |
| `0x00FE`, `0x0107` | буфер обмена с периферией | гипотеза |
| `0x0C7A` | ячейка-«рукопожатие»: ждут `0xA5`, затем пишут `0x7A` | подтверждено последовательностью в коде |

Подробности и цитаты — в `docs/hardware_evidence.md` (адреса и доказательства,
извлечённые из декомпилированного кода) и `docs/hardware_from_pseudocode.md`.

## Требования к UI (заказчик)

- Tkinter.
- Классические **объёмные** кнопки `tk.Button` с `relief=RAISED`, `bd=4`,
  серый «пластик» (`#4a4a52`), при нажатии `relief=SUNKEN`.
- Тёмный фон (`#1e1e22` / `#26262c`).
- Кнопки разного цвета: цифры, операции, служебные (кассир/сервис).
- Экран кассы — крупные зелёные цифры на чёрном.
- Чек печатается в отдельном окне/области на «бумаге».

- Вектор сброса по адресу `0x8000`: `LJMP 0x0A06`. Адрес `0x0A06` **не входит**
  в имеющийся дамп — это вторая половина прошивки (`0x0000..0x7FFF`), которой нет.
- Все 123 функции из `.c`-файла (по `parse_dump`; всего определений 128) лежат в `0x8000..0xFFFF`, значит дизассемблер
  работал именно с `nm27c512n.hex`; вызовы `func_0x1eb6` и т.п. уходят в
  отсутствующую нижнюю половину.
- Известные адреса внешней памяти из декомпиляции: `0x0009`, `0x000B`, `0x0015`,
  `0x0016`, `0x0093`, `0x0094`, `0x00D3`, `0x00FE`, `0x0107`, `0x0C7A`.
  Значения `0x89`/`0xA9` — управляющие слова ППИ 8255, значит ППИ живёт
  по адресам `0x0000..0x0003`.
